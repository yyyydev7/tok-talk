# 데이터 파이프라인

NIOSH 원문 수집·정제·청킹·임베딩·인덱스 생성을 담당하는 독립 작업 영역입니다.
현재는 폴더와 데이터 형식 예시만 있으며, 실행 가능한 수집·적재 기능은 아직 없습니다.
필요한 라이브러리는 파이프라인을 구현하면서 이 폴더의 `pyproject.toml`에 추가합니다.

## 작업 위치

- `pipeline/`: 수집·정제·청킹·임베딩·인덱스 생성 코드
- `data/`: 물질 카탈로그, 출처표, 인덱스 명세
- `data/raw/`: 수집 원문 캐시 (생성 파일은 Git 제외)
- `data/indexes/`: 생성 인덱스 (생성 파일은 Git 제외)

프로젝트 루트 기준 경로는 각각 `datapipeline/pipeline/`, `datapipeline/data/`입니다.
재고 데이터는 backend의 DB 관리 영역에서 관리합니다.

## 개발 환경

Python 3.11.15와 uv를 사용합니다. 이 폴더에서 다음 명령을 실행합니다.

```bash
uv sync --frozen
```

현재 외부 패키지 의존성은 없습니다. 파이프라인이 구현되기 전까지 수집·인덱스 생성 명령은 제공하지 않습니다.
외부 서비스 키를 추가하게 되면 환경변수로 전달하고, 실제 키는 Git에 넣지 않습니다.

## RAG 담당자에게 전달할 내용

1. 확정한 물질 카탈로그와 출처표: `material_id`, CAS, 이름·동의어, 공식 원문 URL
2. 청크 메타데이터: `chunk_id`, `material_id`, `cas_number`, `title`, `section`, `url`, `checked_at`
3. 인덱스 명세: 산출물 버전, 원문 해시, 청킹 규칙, 임베딩 모델·차원·검색 거리, 재생성 명령
4. 해당 명세와 일치하는 물질별 인덱스와 메타데이터

RAG 담당자와 형식을 먼저 합의하고 샘플로 검증한 뒤 전체 데이터를 생성합니다.
검증한 산출물은 팀이 정한 저장 위치에서 전달하고, `rag/` 서버는 전달받은 인덱스를 읽기 전용으로 사용합니다.
서버 시작 시 수집·임베딩 작업을 실행하지 않습니다. `checked_at`에는 실제로 확인한 날짜만 기록합니다.
