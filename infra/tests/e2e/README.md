# 서비스 간 확인

개발 Compose를 실행한 뒤 프로젝트 루트에서 다음 명령을 실행합니다.

    python3 infra/tests/e2e/smoke.py

포트를 바꿨다면 --frontend, --backend, --rag 인자로 전체 기본 주소를 전달하세요.
인증 쿠키를 공유하므로 backend와 rag의 호스트명은 모두 localhost 또는
모두 127.0.0.1로 통일하세요. 요청 Origin은 --frontend 주소에서 가져옵니다.
--frontend 주소를 변경하면 .env의 CORS_ORIGINS에도 같은 주소를 설정하고 서비스를 다시 실행하세요.

데모 Compose를 실행했다면 프록시를 통한 release 화면과 서비스별 전달 경로를 확인합니다.

    python3 infra/tests/e2e/proxy_smoke.py

포트를 바꿨다면 --base http://localhost:변경포트를 전달하세요.
.env.demo의 CORS_ORIGINS도 같은 주소로 변경하고 데모 서비스를 다시 실행하세요.
데모의 기본 주소는 http://localhost:8088입니다. 기본 프로젝트 이름이 개발 구성과
달라 DB 볼륨과 가입 계정도 분리됩니다. 공개 HTTPS 배포를 검사하는 구성은 아닙니다.

두 검사는 공통 인증 검사인 `auth_checks.py`를 사용해 다음 항목을 확인합니다.

- Vue 화면, Java·FastAPI 프로세스 생존, Java 인증 준비 상태
- 임의 계정 가입, 중복 가입 거절, 틀린 비밀번호 거절, 로그인과 JWT 쿠키 검증, 로그아웃
- 로그인 전과 로그아웃 후 보호된 RAG 경로의 401 응답
- 인덱스를 사용할 수 있으면 인증 후 물질 5종의 ID·CAS 번호와 200, 사용할 수 없으면 503 응답
- 아직 구현되지 않은 재고 API의 404 응답과 알 수 없는 경로의 404 응답

RAG `/health`는 재고 DB가 미구현이므로 503을 응답합니다. 검사에서는 이 상태와
`index_ready`를 구분합니다. 인덱스가 없어도 예상한 503을 받으면 검사가 통과할 수 있으므로,
통과 결과만으로 인덱스 준비가 완료되었다고 판단하지 마세요. 기본 인덱스 경로는
호스트의 `datapipeline/data/indexes/current`, RAG 컨테이너의 `/data/indexes/current`입니다.
인덱스가 준비되었다고 응답한 경우에는 실제 모델·인덱스를 읽는 물질 목록 조회도 성공해야 합니다.
첫 모델 로드가 필요할 수 있어 이 요청과 프록시의 응답 대기 시간은 180초입니다.

각 실행은 DB에 임의의 검사 계정 하나를 만들고 삭제하지 않습니다.
인증 쿠키는 검사 프로세스의 메모리에만 보관하며 토큰과 비밀번호를 출력하지 않습니다.
실제 LLM 답변 생성·답변 품질과 재고 조회 성공은 이 검사에 포함하지 않습니다.
화면에서 로그인 후 질문해 답변과 출처가 표시되는지 별도로 확인하세요.
