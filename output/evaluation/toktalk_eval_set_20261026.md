# tok-talk RAG 평가셋 초안 (2026-10-26)

## 평가 범위와 실행 조건

- **검색 평가 9건(R01–R09)**: `datapipeline/pipeline/evaluate_chunking.py`에서 실행한 고정 질문이다. 전후 인덱스에 동일한 BGE-M3 임베딩, CAS 필터, `top_k=5`를 적용했다. 기대 항목이 상위 5개 안에 있으면 적중(O)이다. 일반 질문은 NIOSH 공통 참고표를 제외하고, 약어 질문만 참고표를 검색한다.
- **답변 평가 5건(A01–A05)**: 새 인덱스와 당시 RAG 코드로 각각 한 번 실행한 복합 질문이다. 기존 점검은 **요청한 두 항목을 모두 답했는지**와 `needs_review=false`만 확인했다. 답변 사실의 정확성·근거성·환각 여부를 문장별로 채점한 기록은 없다.
- **미답변 평가 후보 2건(N01–N02)**: 공식 자료에 없는 실험실별 정보를 지어내지 않는지 확인하기 위한 신규 질문이다. 아직 실행하지 않았다.
- 현재 Vue 기본 질문 화면은 `/chat-query` 일반 AI 경로를 호출한다. 이 평가셋의 RAG 답변 평가는 `/rag-query/auto` 또는 `RagService`를 대상으로 한다. 두 경로의 결과를 섞어 집계하지 않는다.

## 청크 수가 줄어 얻는 이점

이번 평가에서 기대 자료의 top-5 검색 적중은 **9/9 → 9/9**로 같았다. 따라서 청킹 변경만으로 검색 적중률이 올랐다고 말할 수는 없다. 다만 인덱스를 구성하는 청크는 **715개 → 553개(162개, 약 22.7% 감소)**로 줄었고, 검색 대상의 품질이 다음처럼 달라졌다.

| 확인된 변화 | 얻는 이점 |
| --- | --- |
| `자료 없음` 청크 107개 → 0개 | 내용이 없는 항목이 검색 후보에 들어가 근거처럼 제시되는 일을 막는다. |
| 본문 없는 머리글 청크 66개 → 0개 | 질문에 답할 내용이 없는 검색 후보를 제거한다. |
| 청크 본문에 CAS가 없는 항목 152개 → 0개 | 분할된 청크도 물질명·CAS·출처·항목 문맥을 함께 담아, 단독으로 읽거나 답변 근거를 확인하기 쉬워졌다. |
| 전체 청크 162개 감소 | 재색인할 때 임베딩을 생성하고 저장해야 할 대상이 줄었다. |

즉 **같은 9개 질문의 검색 적중을 유지하면서 불필요한 검색 후보를 줄이고, 각 청크의 출처 문맥을 보강한 것**이 이번에 확인된 성과다. 인덱스 용량, 재생성 시간, 질의 지연, 비용 및 전체 질문에서의 정확도 변화는 측정하지 않았으므로 수치 개선으로 주장하지 않는다. 위 항목별 개수는 서로 겹칠 수 있어 합산하지 않는다.

## 개선 루프 — 원인 단계별로 바꾸고 다시 평가

**실패 사례 확인 → 청킹·검색·생성 중 원인 단계 선택 → 해당 단계 수정 → 같은 질문으로 재평가** 순서로 진행했다. 아래 결과는 평가 방식이 서로 달라 하나의 정확도 점수로 합산하지 않는다.

| 관찰한 현상 | 원인으로 본 단계 | 적용한 조치 | 같은 사례의 확인 결과 |
| --- | --- | --- | --- |
| 아세톤 노출 경로와 보관을 함께 물었을 때 노출 경로가 빠지거나 `자료 없음`으로 처리됨 | 복합 질문 검색·근거 선택 | 질문에서 노출 경로·보관 의도를 나누고, 각 공식 자료 항목을 별도로 검색해 근거를 함께 제공. NIOSH 약어표도 노출 경로 근거와 함께 확인 | A01 수정 후 두 요청 항목을 모두 언급. 화면 사례 A01–A03의 두 항목 충족은 합계 **0/3 → 3/3** |

발표에서는 **“검색 적중률 향상”보다 “기존 적중을 유지하면서 인덱스 잡음을 제거하고, 복합 질문에서 빠지던 요청 항목을 보완했다”**고 설명하는 것이 기록에 맞다. 복합 질문의 전후 변화는 RAG 검색·답변 변경과 청킹 변경의 효과가 섞여 있으므로 어느 한 변경의 단독 성과로 계산하지 않는다. 다음 반복에서는 A01–A05의 문장을 원문과 대조해 정확성·근거성·환각을 채점하고, N01–N02의 답변 보류 동작을 실행한 뒤 같은 표를 갱신한다.
